# Design

- Prefers full-width, information-dense layouts for admin/console UIs (compact tables and row heights, small/dense controls, multi-column metric grids) over a centered limited-width content column; explicitly rejects the default `mx-auto max-w-*` wrapper. Confidence: 0.7
- Prefers keeping an existing, working capability/library rather than swapping it for a lighter or more modern alternative when the swap risks feature regression (e.g. retaining ECharts over Recharts/uPlot). Confidence: 0.55
- Standardizes admin-console frontends on React 18 + TypeScript (strict) + Vite + react-router-dom, Tailwind CSS v4 (CSS-first, no config file), shadcn/ui with the unified `radix-ui` package, CVA, lucide-react icons, and Geist font. Confidence: 0.55
- Wants a deliberately lean dependency set — no data-fetching/state/form libraries (react-query, SWR, Redux, Zustand, jotai, react-hook-form, zod); prefers small in-house solutions (custom `useAsync`, controlled `useState` forms, inline Alert feedback) instead. Confidence: 0.5
- Prefers styling by convention: semantic design tokens only (no raw colors), layout via flex/grid + gap (never space-x/y), `size-*` utilities over separate w-*/h-*, and `data-testid` on interactive elements. Confidence: 0.5
- Expects conventional, immediately-recognizable console UX affordances rather than custom/minimal alternatives: a leading type-distinguishing icon on each listing row (folder vs file, mount point, worker, transfer/job kind, storage medium), and a standard clickable breadcrumb trail where every hierarchy level is a jump target (current level inert). Confidence: 0.6
- Wants capabilities preserved, not necessarily the controls that provided them: adopting a standard pattern (e.g. clickable breadcrumb navigation) must not remove the ability to reach something the new affordance cannot express — manual path entry (input + Go, for pasting a path not reachable by clicking) stays — while the redundant controls it supersedes (Up/Root buttons) are removed. Confidence: 0.65
- Rejects controls that duplicate a job another control already does: each control should have a single distinct responsibility, and when an existing affordance covers it (breadcrumb `🏠 Root` vs a `Root` button; clickable parent crumb vs an `Up` button) the redundant control is deleted rather than kept. Confidence: 0.65
- Prefers toolbar controls grouped into rows by responsibility instead of one crowded row of unrelated controls — e.g. navigation (trail + manual path input) on one line, operations on the current context (create/upload/free/columns) on the next. Confidence: 0.55
- Wants neutral, achromatic surfaces: backgrounds should be pure white (light mode) and pure black (dark mode) with neutral greys for chrome (borders/muted/input) — not brand-tinted neutrals. The brand color belongs on controls/accents (primary buttons, hover/active/selected states, focus ring) for emphasis, not in the page background or greys. Confidence: 0.6
are not opportunities for brand color, and text must never be rendered in the brand color on top of a brand-colored/tinted surface (explicit rule: "if the background is green, the text should not be green"). Icon grids/lists stay neutral grey and rely on shape for meaning. Confidence: 0.65
- Prefers compact single-column key/value lists (label left, value right, thin dividers) for detail/overview/summary panels — explicitly rejects grids of many bordered rectangle cards, and wants counters collapsed into a single inline row. Confidence: 0.6
- Wants status/state tags color-coded by intuitive semantics (online/healthy/positive green, offline/lost negative red, managed states distinct e.g. blacklist amber vs decommission blue) and applied consistently on every list and detail view. Confidence: 0.6
- Expects table cells to constrain their own width so long values (ids, paths, filenames) truncate — full value available via tooltip — instead of overflowing into and overlapping the adjacent column's label. Confidence: 0.6
- Wants repeated per-row metadata tags/tokens in a listing (e.g. storage-location cv/both/ufs, status labels) to occupy a fixed-width slot pinned to a consistent edge so they line up in a true column across rows — not sit inline after variable-length content (filenames) where their position drifts row to row. Confidence: 0.55
- Expects modal/drawer forms to protect entered data: dismissing one must not silently throw away what was typed. An accidental click on the page behind the drawer should be inert (no close, no prompt), while an explicit dismissal (X, Escape, Cancel) should ask for confirmation before discarding — and a form left untouched should close with no prompt. Confidence: 0.6
- Prefers per-row actions as compact icon-only buttons (lucide glyph with `sr-only`/`title` label) over text buttons, keeping dense tables tight; when an action has variants (copy full path vs. copy filename), prefer a single icon trigger that opens a dropdown menu listing the choices rather than one text button per action. Confidence: 0.5
- Wants navigation to degrade gracefully at extreme depth: for a very deep path, the current directory must stay visible (collapse the middle levels behind an ellipsis menu of jump targets) rather than letting the trail grow into a scrolled strip that pushes the current location out of view. Confidence: 0.5
- Rejects redundant page-level action buttons: an action should be offered only where it is meaningful (e.g. a "Blocks" inspection reachable from a file row's action column), not duplicated as a header button on the page that contains that list ("很突兀", "没必要再增加这么一个按钮"). Confidence: 0.7
- Wants a given UI slot to mean the same thing across related views: a corner/position must not carry opposite meanings on adjacent pages (e.g. "go deeper" on one page, "go back" on the next). A child/leaf view should reuse its parent's navigation affordance — the same breadcrumb trail in the same position — for going back, instead of introducing its own Back button. Confidence: 0.6
- Wants every list row to be a single line of content, consistently across all lists (workers, jobs, transfers) — stacked multi-line cells (name over id, source over target plus message, percentage over meter) are flattened so one row = one line and row height no longer varies with content. Confidence: 0.6
- Accepts resolving a row from multi-line to single-line by moving the secondary content out of the visible line (full id/path into the hover title and click-to-copy, warning text behind a small warning icon) rather than dropping it or adding a dedicated column — nothing may be lost, it just stops consuming line height. Confidence: 0.55
- Wants an existing control/pattern reused verbatim on sibling pages instead of a bespoke variant per page — e.g. "give the transfer list the same 显示列 (show columns) filter the file browser has" — so comparable lists behave and look the same. Confidence: 0.6
- Prefers a listing's detail view to open as a right-side slide-out panel layered over the still-visible list instead of replacing it with a separate page; the list stays mounted behind it and the direct route/deep link (`/workers/<id>`) keeps working. Confidence: 0.6
- Wants an overlaid detail panel positioned/sized off the console's real content box rather than a hard-coded sidebar arithmetic — it must line up with where a full page's content sits (padding included) at every breakpoint and sidebar state (expanded / collapsed / off-canvas), but sized deliberately *smaller* than that box: ~80% of it, leaving a strip of the underlying list visible so the panel reads as a layer ("稍微窄一些吧，大小为原来的 80%；这样有层级的效果"). Confidence: 0.7
- Expects every slide-out panel to animate on dismissal — the panel slides out while the backdrop fades, instead of vanishing instantly — and wants that behavior applied to all slide-out panels, not only the one reported ("所有目前侧滑呼出的页面，退出也应该是滑动消失"). Confidence: 0.65
- Wants a metadata value that is meaningful to compare across rows (e.g. a worker's reported build version) promoted to its own labeled column instead of being stacked inside another cell's subtitle or hidden behind a hover title. Confidence: 0.55
- Wants console layouts to be screen-adaptive rather than fixed-size: on a small window the content must fit without horizontal page scrolling. Rejects hard-coded widths (per-table `min-w-[…]` floors, fixed panel sizes) that push the whole page — header and sidebar included — wider than the viewport; treats this as a systemic/global sizing concern rather than a per-page tweak ("应该做到屏幕自适应"). Confidence: 0.75
- Wants a splitter/rail that *looks* draggable to actually be draggable, and expects dragging it narrow to snap the pane into its compact mode (e.g. sidebar collapsing to a pure icon rail) instead of squeezing labels into unreadable widths — pulling back out restores the full pane. Confidence: 0.7
- Wants sibling slide-out panels to be positioned identically, each reaching the window edge flush (the shared sheet variant's `right-0`) — a panel that insets itself by content padding/scrollbar so a strip of background shows on one side is treated as a defect, and the outlier should be aligned with the other panels rather than given its own bespoke position math. Confidence: 0.6
- Wants transient feedback for actions and state changes (e.g. "任务 ID 已复制" / copied confirmations) surfaced as a bottom-right Toast popup, not as inline text that occupies a row of the page — confirmations should not push layout or take up listing space. Confidence: 0.7
