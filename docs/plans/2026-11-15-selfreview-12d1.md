# 独立自审 — 冻结源 12d16e7af（执衡第 7 轮驳回后）

## 1. publish 窗口的数据丢失（驳回成立，已修）

**驳回事实复核**：`flush_inner` 成功即 `finish_flush_all` → `flushing=false`；
随后才 `publish_writer().await`。`evict_inodes` 期间调 `free_pages(false)`，
此时页既不 dirty 也不 flushing → `retain` 返回 false → `page.clear()` +
`release_usage`。若 publish 再失败，`restore_flushed_dirty` 的 `get_mut` 静默跳过。
**数据确实会丢。**

**修复（保护范围覆盖整个 flush+publish）**：
- `flush_inner` **不再清 flushing**（代码内有注释说明这是刻意的保护，不是遗漏）；
- 三个调用点 `flush_all` / `flush_dirty(sync)` / `publish_read_range` 统一为：
  `take → snapshot → flush_inner → publish_writer → 成功 finish_flush_ids / 失败 restore_flushed_dirty`；
- `restore_flushed_dirty` 对"页已不在"不再静默：`warn!` + `restore_lost` 指标。
- 因为 `flushing` 全程为真，`free_pages(false)` 在整个窗口内都会保留页，
  `get_mut` 命中有保证；这不是"再加一个判断"，而是把保护期覆盖到 publish 结束。

**取消/panic**：`flush_inner` 失败分支先 restore 再返回；`restore` 与 `finish`
都在 `.await` 聚合之后同步执行，没有跨 await 持锁。panic 会走 unwind（页仍
flushing → evict 不清，usage 不释放，属保守安全侧）。

## 2. `complete` 失败仍 `free_pages(true)`（驳回成立，已修）

`complete` 末尾原本无条件 `free_pages(true)`。complete 失败 ≠ 用户删除，
配合新恢复逻辑会把刚恢复的脏数据再次 force 清掉。改为**仅 `res.is_ok()` 时** free。
`truncate` / 删除 / TTL 的 force 语义保持不变（那是明确的丢弃契约）。

## 3. `take_*_dirty_pages` 中途失败丢弃已 take 的页（驳回成立，已修）

`take_dirty_pages_inner` / `take_dirty_pages_range` 循环内 `take_dirty(..)?`：
较后页出错时，前面已 take 的页保持 `flushing=true`、ranges 已移出，`result` 被
drop → 静默丢数据。改为 `Err(e)` 分支先 `dirty_snapshot(&result)` +
`restore_flushed_dirty`（释放写锁后调用，避免自锁），再传播错误。

## 4. 确定性交错测试（不依赖并发时序、不靠 sleep）

- `eviction_cannot_reclaim_a_page_awaiting_publish`：
  1. `take_all_dirty_pages()` 模拟"flush 在飞"（flushing=true）；
  2. `free_pages(false)` **必须返回 0**、`cm.used()` 不降 —— 直接证明 evict 无法
     在 publish 前清页；
  3. 模拟 publish 失败 → `restore_flushed_dirty` → `cm.used()` 不变；
  4. 换健康 writer 重试 → 后端落盘 **4096** 字节（数据真的被重发）。
- `complete_failure_keeps_dirty_pages`：`/dev/full` 后端下 `complete` 必须 Err，
  且 `cm.used()` 不降。

这两条替换了"只靠 `/dev/full` + 手工换 writer 推断失败安全"的证据缺口。

## 5. 生产恢复语义（不把内部测试说成生产路径）

诚实边界：`set_error` 之后该 inode 的写入被 fence（返回 EIO/ENOSPC 类错误），
**本次调用点不提供自动重试**。缓存内数据保留（不再丢弃），但恢复需要重新建立
writer（重启/重新打开/管理员介入），当前实现**没有**"错误清除后自动续传"的通路。
`free_pages(false)` 保留脏页使这份数据在进程存活期间可被诊断/重试，但不是用户
可见的自动恢复。以上为本轮的事实边界，不宣称已实现生产级 self-healing。

## 6. 性能：单一所有权，不复制页数据

恢复只需要 `(page_id, dirty_ranges)`；数据仍由 taken `Page` 持有。因此新增
`dirty_snapshot`（只复制 ranges 向量，页数据零复制）。曾尝试
`Page::flush_snapshot()` 完全避免 ranges 复制，但 `StoreInner::Disk(LocalFile)`
不可 clone（复制需重开文件/额外 IO），故放弃，选择"ranges 一份快照"这个
最小代价方案。flush 热路径未新增页级内存复制。
