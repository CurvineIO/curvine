## 0. 第 6 轮四条逐项

### 1) `evict_inodes` 失败即 `force` 清页 —— 确认为真实数据丢失，已修

**驳回成立**。原实现 `flush` 失败 → `cache.set_error` + `free_pages(true)`，
而 `free_pages` 的 force 分支直接 `page.clear()`：把恰好未持久化的
dirty/flushing 页清掉，用户写入静默消失。

**更深的既有缺陷（顺全流程核实后一并修）**：`flush_inner` 用
`take_*_dirty` 把 `dirty_ranges` **`mem::take` 走**，失败时只
`finish_flush_all` 清 flushing 标志，**不把 ranges 还回原页**。于是数据既不在
后端、也不再被当作脏页。原测试 `write_back_flush_failure_drops_dirty_state`
甚至把这一丢数据行为写成预期（"failed flush must not leave dirty ranges for retry"）。

**失败点不止写入**：`publish_writer`（真正把数据推给后端/发布脏读快照）发生在
`flush_inner` **成功之后**，此时脏标志已清；它失败同样会丢数据。因此：

| 位置 | 修复 |
|---|---|
| `flush_inner` | 写前快照 `(page_id, dirty_ranges)`；**失败 → `restore_flushed_dirty`**（`Page::restore_dirty` 重新 mark_dirty 并清 flushing）；成功才 `finish_flush_all` |
| `flush_all` | take 后自持快照；`publish_writer` 失败 → restore + 返回错误 |
| `flush_dirty` | 同上（sync 分支） |
| `publish_read_range` | 同上 |
| `evict_inodes` | **删除 force 分支**：失败只 `set_error` + 计指标，一律 `free_pages(false)`（保留脏页） |

**backpressure 与错误传播**：保留的 usage 让 `need_evict()` 持续为真，写路径走既有
ENOSPC/fallback（`write_back_fallback_direct_write_on_enospc` 覆盖）；`set_error`
把该 inode 后续写入挡住并向上传播错误。丢弃语义只保留给显式场景
（删除 / TTL / `complete` 后的 `free_pages(true)`），那三处调用点未改。

**可控后端错误测试**（不靠成功用例推断失败安全）：
`write_back_flush_failure_keeps_dirty_state_for_retry` 用 `/dev/full` 制造真实写失败，断言
1. `flush()` 返回 Err；
2. `cm.used()` **不下降**（页未被释放，数据未丢）；
3. 换回健康 writer 重试后，后端落盘字节数 = **1024**（原写入量）——
   证明 retained ranges 被真正重发，而不是"看起来还在"。

### 2) A/B harness 层次 —— 承认不可比，不冒充客户端测量

**驳回成立**。`curvine-master/tests/metadata_ab_bench/ops.rs` 直接调用
`MasterFilesystem::set_attr` / `complete_file`，**不经过** `FuseWriter` /
`UnifiedWriter` / `FSWriterBuffer`，因此本轮装箱（`WriterTask::Complete/Resize`、
`MirrorTask::Complete`、`WriteTask::Complete/Resize` 的 `Box<SetAttrOpts>` /
`Box<FileAllocOpts>`）产生的分配与延迟**不在**该 harness 的测量范围内。

更正后的口径：
- 该 harness 是 **Master 元数据层**基准，`set_attr`/`set_attr_mtime`/
  `complete_file`/`complete_file_mtime`/`resize` 在本层**可比**（同 API、同基线），
  可作为 master 侧性能项；
- 它**不能**用于评估客户端装箱影响。客户端层本次只做了**功能验证**：
  `curvine-fuse --lib` 638（含 complete Some/None、mtime 透传、resize 顺序、
  错误传播、cancel 语义）、`client-core` 73、`unified-fs` 33；
- 若需客户端性能结论，必须另建 client/fuse 端 harness（需真实集群 + FUSE 挂载），
  本轮**未做**，属明确限制，不用 master 吞吐冒充。

op 数量：`ops::CASES` 由 **19 → 21**（新增 `set_attr_mtime`、`complete_file_mtime`），
`main.rs` 遍历 `CASES`，调度代码未改。

### 3) raft 300ms 窗口的措辞 —— 改为事实边界

改为：窗口（≥ `rpc_retry_max_duration_ms`）**只能否决在窗口内到达的**重复投递；

不具备；**承重断言是上面那条 durable-log 检查**（该 payload 只有一条 entry）。
本文件同步采用同一口径，不宣称已证明。
